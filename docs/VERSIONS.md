# 两版机制与边界

## 初步改进（initial_improvement）

长期视觉向量数超过400时，选择总代价最低的时间相邻事件对，生成必要的文字补偿，再合并视觉向量。如果仍超过400，最旧事件转为常驻 KV；随后循环。一次合并已满足容量时，不发生转KV。

合并代价是 `0.4*(1-s) + 0.2*T + 0.4*F`。s为拼接事件向量的二分匹配相似度均值；T为两个代表秒时刻的平均值除以当前秒时刻；F为候选相邻对包含的初始事件数量均值除以所有候选对均值的最大值，再加原实现的微小正数。代表秒时刻合并时按原始帧数加权。

摘要生成在现存主 KV 之后临时追加输入，因此两事件之外的旧历史视觉 KV 也可见。生成结束截去后缀；文字重写也存在这一隐式历史上下文。

## 最新确认（latest）

每次长期区超额，先判断**最老事件及其直接后继**，不是全局最低代价候选对：

1. 最老事件合并树深度≥3，或与直接后继的匹配相似度严格小于0.7：转出最老事件。
2. 否则选择全局代价最低的相邻事件对合并。
3. 一次动作后容量满足即停止，仍超额则重新判断。不存在合并后无条件再转出。
4. 只剩单个超大事件时直接转出，原因单列。

合并树深度初始0、合并取 `max(d_left,d_right)+1`；初始事件数量初始1、合并相加。两种计数分开，后者继续参与代价。

时间代价改为 `((p_left+p_right)/2)/(frames_seen-1)`。新事件代表采样帧位置为此前已形成事件的帧数加 `(当前事件帧数-1)/2`；合并按两侧当前视觉 token 数加权。与 StreamForest 的采样帧/压缩后帧槽口径对齐；Qwen每帧向量数可变，因此用实际 token 数实现帧槽权重。仍是归一化位置，不是倒数年龄或另一个衰减函数。它不改变 Qwen M-RoPE 位置张量。

摘要只复制系统前缀到临时 GPU 缓存：补充摘要看合并前两事件的当前视觉向量及其已有笔记；重写只看拼接笔记。其他旧视觉KV、Recent、短期及未来问题均不可见。主KV留在GPU，完成或异常后恢复原缓存、位置与评分捕获状态。文字位置保留主缓存的绝对位置下界，避免隔离后坐标从头开始。峰值KV字节同时统计主缓存与临时缓存。

新记录包含超额管理轮次、逐次决策、合并次数、深度/相似度/二者同时/单事件转出、操作前后大小、最老事件深度与相似度、累计转出向量数和代表帧位置。转出概率分母应为管理决策次数；两条件同时命中仍只计一次转出。匹配结果在本轮复用，避免同一最老相邻对重复计算。

## 两版共有

- Qwen2.5-VL-7B-Instruct，BF16，FA2，0.5 FPS，2帧/chunk，最大边336，独立图片编码。
- Recent名义50，整帧无法容纳时按原规则回退到400；短期不是无限候选缓存，最旧8帧中找相邻相似度最低的可用边界，常规事件至少2帧，问题到达封闭尾部。
- 退出Recent逐帧减半一次，形成事件后跨帧拼接再减半；长期400视觉向量。二分匹配合并保留原有累计权重和代表位置。
- 独立常驻视觉KV预算1000/层，不含系统前缀和临时输入。全局文字2000 token、单事件100、新增/重写最多64（自回归生成上限，可提前EOS）。
- 选中合并对总代价严格大于0.3才生成补偿文字；已有笔记按顺序拼接，超过100才重写到64以内。全局超2000裁去最旧文字，并同步维护评分用Q。转KV本身不会自动生成摘要。
- N参考最近4个chunk的均值；A用中间锚点层的活跃、因果可见KV计算入向注意力；N/A跨层共享，D逐层。S=0.3N+0.4D+0.3A（各信号沿用归一化）。
- KV超额时，对所有事件逐事件逐层减半；首次才评分，继续减半复用排序，无S写入阈值。已删除视觉与KV没有CPU备份。
- 无文字用事件末尾视觉Q，有文字用放在视觉之后的摘要Q；查询窗口32。
- 回答时：常驻旧KV + 关联文字 + 未转出的长期视觉及其文字 + Recent，原生Qwen注意力。常规选择题自由贪心输出最多16，Forward最多64，不强制首token选项。
- 深度5、相似度0.8、强化“准备/完成”重写提示及Forward统一16等中间实验，均不是本次latest显式配置。

请以版本YAML为准，不要依赖配置类为了旧消融保留的默认值。改配置用于新实验时应另存输出目录。

## 历史结果与复现边界

初步改进对应既有 OVOBench 12任务 / 3035问结果：1431正确，微平均47.15%；Backward宏平均48.75%，Realtime宏平均65.98%，Forward宏平均40.52%，三组等权总平均51.75%。Realtime为546/837（微平均65.23%）。以上是原实验框架中的历史结果，不是此精简发布包重新运行后的结果。

latest是最新确认机制的代码组合，尚无完整全量结果。不要把初步改进成绩、不同阈值小样本或单独提示词实验当作latest全量成绩。StreamingBench结果仍待后续汇总。

本仓库保留两版科学核心，剥离其他方法的调度框架，新增轻量包装与评测命令；核心源文件哈希见source_provenance.json。视频采样、问题模板、原生解码、评分公式来自已有实现。新入口已通过CPU小模型与数据预检，但尚未进行7B/FA2整条评测数值回归；需要在同一硬件上用同一问题清单确认后，才能声称与历史运行逐问完全一致。
